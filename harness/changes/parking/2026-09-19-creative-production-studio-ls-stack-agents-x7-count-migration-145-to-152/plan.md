## Interfaces, Data, Permissions

- Registry YAML is the single source of truth; JSON mirror for dashboard/router/executor regenerated via `ai-company sync-registry`.
- New cards emit `mode: subagent` + `permission:` blocks derived by `_TOOL_MAP` (execute->bash, write/edit->edit, web_search/websearch->webfetch, delegate->task, plus read/grep/list/question). Unknown tools are rejected by ToolRunner, so only canonical names are used.
- Cross-refs validated by `RegistryResolver`: specialist `reports_to` must resolve; `creative_director` and its six reports are all specialists resolving to `cmo`/`creative_director`.

## Spec Gaps Found From Planning

- `ai-company specialists add` CLI only supports id/title/department/reports_to/specialization — cannot express description/responsibilities/guidelines/model_tier, so registry entries are hand-author-written; the CLI is not used.
- `docs/AGENT-REGISTRY-TABLE.md` is a generated file and is drift-gated only via regeneration, not a static count edit.
