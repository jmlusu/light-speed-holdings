- **Design system reference:** Color usage rule #2: "Secondary CTA ΓåÆ navy border (light) / white border (dark), navy text (light) / white text (dark)"
- **Refinement needed:** The "Request an AI Readiness Assessment" outline CTA currently uses red border/navy text, but the design system specifies navy for secondary CTAs. Consider updating to navy border with navy text on light mode and white border with white text on dark mode, OR document this as an intentional brand variant if red is desired for secondary actions.

### [HIGH] Color Compliance: Both CTAs use red; secondary should use navy
- **Evidence:** `HomePage.tsx` ΓÇö primary CTA has `bg-ls-red text-ls-white`; secondary has `border border-ls-red text-ls-red`
- **Design system reference:** Rule #1: "Primary CTA ΓåÆ Always red background, white text"; Rule #2: "Secondary CTA ΓåÆ navy border (light) / white border (dark), navy text (light) / white text (dark)"
- **Refinement needed:** The primary CTA correctly uses red per rule #1. The secondary CTA should use navy border/text per rule #2. This is the same compliance issue as #1 viewed from a different angle ΓÇö both need attention in the same change.

### [MEDIUM] Accessibility: Hero image has empty alt attribute
- **Evidence:** `HomePage.tsx` line 33 ΓÇö `<img src="/brand/digital/Homepage_Hero_High_fidelity.jpeg" alt="" />`
- **Design system reference:** ┬º649: "Every image carries meaningful alt text (Accessibility)"; ┬º640: Type A hero imagery is "cinematic hero imagery (African tech/business context, Lilongwe geometry)"
- **Refinement needed:** Provide meaningful alt text describing the hero imagery. Since this is Type A hero imagery with African tech/business context, the alt text should describe the content (e.g., architectural geometry, Lagos skyline, data center, or other Lilongwe/organizational imagery). Per the prohibition on stereotypes (Directive ┬º19, line 1088), avoid generic stock-photo smiles or clich├⌐d imagery descriptions.

### [MEDIUM] Accessibility: CTA buttons use focus-visible:outline-none
- **Evidence:** `HomePage.tsx` lines 60-61 and 68-69 ΓÇö both CTA buttons have `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ls-red focus-visible:ring-offset-2`
- **Design system reference:** Accessibility section ┬º32: "Visible Focus ΓÇö 2px cyan outline, 2px offset (actual implementation)"; `src/index.css` `:focus-visible { outline: 2px solid var(--ls-cyan); outline-offset: 2px; }`
- **Refinement needed:** The `focus-visible:outline-none` pattern removes the default browser outline and relies on the custom ring. Verify this meets WCAG contrast and visibility requirements across browsers. Consider whether the custom cyan ring (`var(--ls-cyan)`) on the red-focused buttons provides sufficient focus visibility, or if `outline-none` should be removed to preserve the default focus ring for keyboard users.

### [MEDIUM] Accessibility: Dark mode hero text contrast needs WCAG AA verification
- **Evidence:** `HomePage.tsx` ΓÇö dark mode hero has `bg-ls-navy/80` with `bg-black/60` overlay and `text-ls-white/90`
- **Design system reference:** Navy `#070A40` is for "Headlines, logo text, primary brand surfaces, primary backgrounds"; white `#FFFFFF` is for "Clean backgrounds, text on navy"
- **Refinement needed:** Verify the contrast ratio of white/90 text on navy/80 with black/60 overlay meets WCAG AA (4.5:1 for normal text, 3:1 for large text). The black overlay at 60% darkens sufficiently, but should be tested with actual contrast ratios. Consider using the design system's `--ls-on-navy: #FFFFFF` white-on-navy token instead of composing alphas.
