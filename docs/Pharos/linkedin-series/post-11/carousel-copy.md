# Carousel Copy - Post 11: Lessons From Building LightSpeed

**Card structure (per plan §4):** 4 cards - Start → Breakthrough → Lesson → Future

## Card 1: Start

**Title:** Where It Started

**Key Point:** Systems grow by accretion: scripts from session prompts, one-off agents never retired, configs only I understood. The registry did not exist yet, so nothing downstream could be trusted. First lesson: you cannot retrofit governance onto an inventory you never took.

## Card 2: Breakthrough

**Title:** The Breakthrough

**Key Point:** Three shifts, in order:
1. Queues before chat - coordination became data
2. One matrix for everything - ADR-017's five tiers, every department
3. Publish the ugly numbers - utilization 1.5% against an 80% target, nulls rendered honestly

## Card 3: Lessons

**Title:** Six Lessons

**Key Point:**
- The registry is the product (152 → 90, ADR-032)
- Reliability failures are governance data
- Autonomy earned per action class
- One human standard, uniformly
- Sovereignty is a default, not a claim
- Cost is a dial, not a contract

## Card 4: Future

**Title:** What Comes Next

**Key Point:** 90 agents, 20 departments, five-tier governance, KPIs computed from real sources. The framework: H → A → O → M → T → G → V. Next: sector deep-dives - health, financial inclusion, public service - where the same seven layers meet different constraints.
