# Carousel Copy - Post 9: Measuring AI-native Organizations

**Card structure (per plan §4):** 4 cards: Input → Process → Output → Outcome

## Card 1: The Measurement Chain

**Title:** Input → Process → Output → Outcome

**Key Point:** The measurement chain mirrors an OKR tree. Input: what did we fund and equip. Process: did the system work as designed. Output: what shipped. Outcome: did the organization get better. Skip a level and you get vanity metrics.

## Card 2: Process Metrics (Day 30)

**Title:** Five Numbers by Day 30

**Key Point:**
- One registry (the denominator that makes per-agent metrics computable)
- One queue (throughput and failure are only data if work is queued)
- Utilization weekly (KPI-003: active agents ÷ registered agents)
- Success rate (KPI-004: completed ÷ completed + failed)
- Dead-letter count (where failure landed)

## Card 3: The Honesty Test

**Title:** Publish the Low Numbers

**Key Point:** Our KPI-003 reads 1.5% against an 80% target. KPI-004 reads 100%. Publishing both is the credibility strategy. And where no real source exists yet, the KPI reads null, rendered "n/a", never a hardcoded comforting number.

## Card 4: Outcome Metrics (Day 90)

**Title:** By Day 90

**Key Point:** Cost per agent on the invoice. Decisions by approval tier. SLA adherence per workflow. Department trend on a live org graph. One outcome metric with a real source behind it. Value proven, not promised.
