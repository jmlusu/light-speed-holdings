# SADC Agentic AI Governance Framework

*Policy briefing & executive submission.*
**Author:** Jack Mlusu, Founder & CEO, Lightspeed Holdings (Pharos policy track).

**Target audience:** SADC Member State digital/ICT ministers, telecom & data
regulators (e.g. MACRA, CRASA), central banks, enterprise C-suites, regional
development banks.

**Objective:** a unified, forward-looking operational and regulatory standard for
deploying autonomous agentic AI across SADC.

## Why SADC Needs Its Own Frame

Static, cloud-centric governance built for Western or East Asian contexts fails
against SADC's constraints:

- **Low-bandwidth, intermittent edge environments** requiring localized, efficient model execution.
- **Dual economies** where agents must bridge formal banking (RTGS/SWIFT) and
  mobile money (Airtel Money, TNM Mpamba).
- **Cross-border trade** under the SADC FTA and AfCFTA where automated actions
  cross borders in real time.

SADC cannot regulate reactively after failures. Clear technical parameters now
attract investment and foster domestic enterprise.

## Core Principles

```
            [ SADC Agentic AI Principles ]
     ┌──────────┬──────────┬──────────┬──────────┐
     ▼          ▼          ▼          ▼
   Agency     Sovereignty Financial  Traceability
   Control                  Safety
```

### 1. Graduated Autonomy & Human-in-the-Loop (HITL)

| Tier | Risk | Example | Control |
|------|------|---------|---------|
| 1 | Low — Advisory | aggregation, drafting | No automated execution without human output confirmation |
| 2 | Medium — Automated workflow | internal logistics, routine DB updates | Automated execution with real-time logging |
| 3 | High — Direct execution | financial disbursements, health records, border processing | Mandatory HITL authorization checkpoints |
| 4 | Critical — Infrastructure | power grid, telecom switching, water | Autonomous execution prohibited; decision-support only |

### 2. Cryptographic Identity & Immutable Audit Trails

- Machine-readable **agent credentials** (Agent ID, deployment hash, owning legal
  entity) bound to a registered entity; embedded in API authorization headers.
- **Append-only action logs** for High/Critical tiers: tool invocations, prompts,
  memory retrieval, outputs, state changes — tamper-evident.

### 3. Data Sovereignty & Edge-Compute Standards

- Sovereign **in-country processing** for state, health, and primary financial data.
- Encourage **open-weight, locally hosted models** capable of air-gapped inference
  to survive undersea-cable disruptions.

### 4. Liability & Accountability

- **Agency-as-Instrument:** agents hold no legal personality; liability rests on
  the deploying legal entity and operator. Vicarious corporate liability for
  delegated-credential actions.
- **Programmatic kill switches** and rate limiters for enterprise multi-agent
  deployments.

## Cross-Border Execution Liability

Harmonize liability when an agent hosted in Country A executes an action impacting
assets in Country B. Standardize protocols for automated customs, trade
documentation, and currency settlement; require cryptographic signing
(PKI) of all agent external communications.

## Technical & Operational Standards

| Domain | Standard | Verification |
|--------|----------|--------------|
| System identity | Machine-readable agent credentials | Automated API-gateway audits by regulators |
| Audit trails | Deterministic execution logs | Immutable append-only ledger for High/Critical tiers |
| Model alignment | Prompts/tool boundaries aligned to law & ethics | Independent third-party algorithmic audit pre-deployment |
| Credential mgmt | Scoped API keys; no master keys in agent memory | Zero-trust architecture checks |

## Sectoral Blueprints

- **Financial / mobile money:** automated transaction caps; multi-agent fraud
  monitoring with real-time account isolation; regulatory sandbox for agentic
  micro-lending and insurance claims.
- **Public sector / health / M&E:** autonomous M&E over public health, agri
  yield, and infrastructure audit data; privacy-enhancing tech and federated
  orchestration.
- **Critical infrastructure / logistics:** corridor and port-queue optimization;
  strict air-gapping of OT control loops from internet-connected planning agents.

## Roadmap

**Phase 1 — Standardization (M1–6):** draft model framework & technical
guidelines; establish a SADC Agentic Agent Sandbox network.

**Phase 2 — National Enactment (M7–12):** align MACRA/regional regulatory policy;
launch executive & developer certification.

**Phase 3 — Operational Harmonization (M13–24):** deploy cross-border agent
identity registries; host the SADC Annual Agentic AI Governance Summit.

## Immediate Recommendations

1. Establish a **SADC Multi-Agent Regulatory Sandbox**.
2. Draft **SADC Machine-Identity Guidelines** for verifying automated software requests.
3. Fund **localized capability infrastructure** (multi-agent orchestration,
   security auditing, local-language alignment — Chichewa, Swahili, Portuguese).

## Conclusion

By enacting clear, practical governance standards tailored to regional realities,
SADC can protect critical systems while positioning Southern Africa as a global
leader in sovereign, autonomous enterprise architecture.
