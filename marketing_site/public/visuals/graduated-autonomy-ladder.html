The Graduated Autonomy Ladder

ASPIRE. ACT. ACHIEVE.

Four tiers. Four risk classes. One rule: the control a domain demands scales with the damage an agent could do there. Advisory drafting is not power-grid switching, and policy should not treat them the same.

HONEST STATUS Policy proposal by LightSpeed Holdings' CEO. Not adopted by SADC or any government. No paid client deployments yet. This page presents a governance framework for debate. It describes no deployed production system and claims no regulatory endorsement.

Bandwidth & infrastructure

"Our bandwidth and infrastructure cannot support this."

THE ANSWER

Offline-first, sovereign-by-default deployment that runs inside the ministry's own network, with a zero-cloud option where policy demands it.

Data protection

"Where does our data actually go?"

THE ANSWER

In-country processing for state, health and primary financial data; open-weight models hosted locally, capable of air-gapped inference.

Source: docs/Pharos/policy-drafts/sadc-agentic-ai-governance-framework.md §3

Technology debt

"We cannot rip and replace our legacy core."

THE ANSWER

90-day co-built pilots and integration seams instead of a rip-and-replace programme. Legacy cores keep running while one workflow moves. Debt tracked in a ledger, not a disclaimer.

Working systems plus a strict evidence ladder: a claim advances a rung only where evidence exists. That is the only durable answer to skepticism.

3What each rung demands: the control floor

Identity: every agent is traceable

  • Machine-readable agent credentials (Agent ID, deployment hash, owning legal entity), embedded in API authorization headers.
  • Scoped API keys; no master keys held in agent memory, verified by zero-trust architecture checks.

Source: sadc-agentic-ai-governance-framework.md §2 + Technical & Operational Standards

Audit: every action is replayable

  • Append-only action logs for High/Critical tiers: tool invocations, prompts, outputs, state changes, tamper-evident.
  • Independent third-party algorithmic audit before deployment.

Source: sadc-agentic-ai-governance-framework.md §2 + Technical & Operational Standards

Sovereignty: data does not leave the jurisdiction

  • Sovereign in-country processing for state, health and primary financial data.
  • Open-weight, locally hosted models capable of air-gapped inference, surviving undersea-cable disruptions.

Source: sadc-agentic-ai-governance-framework.md §3

Accountability: a human, not an agent, is liable

  • Agents hold no legal personality; liability rests on the deploying legal entity and operator.
  • Programmatic kill switches and rate limiters for enterprise multi-agent deployments; PKI signing of all agent external communications.

Source: sadc-agentic-ai-governance-framework.md §4 + Cross-Border Execution Liability

Why a floor, not a ceiling: these are the minimum controls the framework attaches to agentic deployment. The ladder then adds tier-specific requirements on top: real-time logging at Tier 2, mandatory HITL checkpoints at Tier 3, a hard prohibition at Tier 4. The framework's first immediate recommendation is a SADC Multi-Agent Regulatory Sandbox to test these controls before enforcement.

Two ladders: do not conflate them

The risk tiers above are a policy taxonomy: they classify whole domains by what is at stake. LightSpeed Holdings separately runs an operational taxonomy inside its own engineering stack: it gates each individual action before it executes. Different jobs, different numbering. Reading them as one ladder would misread both.

POLICY: SADC DRAFT TIERS 1–4

Classifies domains by risk. Advisory → automated workflow → direct execution → critical infrastructure. Set by the regulator for a sector. Source: sadc-agentic-ai-governance-framework.md §1.

OPERATIONAL: LIGHTSPEED HITL TIERS 0–4

Gates individual actions by approval weight. T0 Auto-Approve → T1 Notify → T2 Single Approver → T3 Two-Person Rule → T4 CEO Only. Sources: src/ai_company/orchestrator/tier_rules.py · src/ai_company/executor/hitl_gate.py.
