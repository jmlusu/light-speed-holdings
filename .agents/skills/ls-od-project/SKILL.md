# Open Design Projects

Open Design projects are the unit of work for `od run`. A project owns its Design Files, the skill it generates with, the attached design system, and its conversation and run history.

## When To Use

- Starting a prototype, deck, or document that will be generated by `od run`.
- Importing a folder of existing assets instead of starting blank.
- Turning an existing project into a design-system workspace.
- Cloning a project to branch a direction without touching the original.
- Checking what a project is, which skill it uses, or where its files live.

## Project Model

| Piece | Set at | Meaning |
|---|---|---|
| `--skill <id>` | `create`, `import-folder` | Template/skill the project generates with |
| `--design-system <id>` | `create`, `import-folder` | Brand system applied to output |
| `--mode design\|chat\|plan` | `create` | Default working mode |
| Design Files | Owned by the project | Copied by `duplicate` |

A project id is stable. `duplicate` and `create-design-system` always mint a new id and leave the source project untouched.

## Commands

Create a project with an explicit skill and design system:

```bash
od project create --name "Landing page" --skill web-prototype --design-system lightspeed
```

List projects:

```bash
od project list
```

Duplicate a project and copy its Design Files (use this to branch a direction):

```bash
od project duplicate <id> --name "Landing page - variant B" --json
```

Turn a project into a design-system workspace and seed the generation prompt:

```bash
od project create-design-system <id> --name "LightSpeed DS" --prompt-file ./ds-brief.md --json
```

Inspect one project:

```bash
od project info <id>
```

`od project info` prints the project object; use it to confirm the id, name, and file location before a run.

## Importing A Folder

`import-folder` seeds a project from files already on disk, then attaches a skill and design system:

```bash
od project import-folder ./site --name "Existing site" --skill web-prototype --design-system lightspeed --json
```

- The path is the folder to import; its contents become the project's Design Files.
- Pass `--skill` and `--design-system` at import time — there is no later flag to attach them to an existing project.
- The daemon call mints a short-lived CLI import token (`x-od-desktop-import-token`) and posts to `/api/import/folder`; no separate auth step is needed.
- `od project import <baseDir> [--name "<title>"]` is the older import form. It takes no `--skill` or `--design-system`, so prefer `import-folder` for branded work.

## Output Locations

Projects write under `output/design`, set as `baseDir` in `.opencode/integrations/open-design/config.json` and `agent-config.yaml`:

| Artifact | Path |
|---|---|
| Websites / prototypes | `output/design/websites` |
| Decks | `output/design/decks` |
| Documents | `output/design/documents` |
| Diagrams | `output/design/diagrams` |
| Infographics | `output/design/infographics` |
| Ads | `output/design/ads` |

## Rules

- Attach `--design-system lightspeed` for any LightSpeed-branded work.
- Never hand-edit a project's Design Files while a run is active; let the run finish or cancel it.
- Branch with `duplicate` or `create-design-system`; never mutate the source project in place.
- Do not invent skill or design-system ids. Confirm template ids from `open-design/design-templates/` and design-system ids from the installed systems.
- Importing copies files into the project; it does not link back to the source folder.
- `od project restore-automatic-scenario` and `od project artifact-snapshot` are recovery surfaces — use them only when a project or artifact is damaged, not as part of normal creation.

## Verification

```bash
od project info <id>
```

Confirm the returned project exists, carries the intended skill and design system, and points at the expected file location. If the design system is missing, recreate the project with `--design-system lightspeed` rather than patching files.
