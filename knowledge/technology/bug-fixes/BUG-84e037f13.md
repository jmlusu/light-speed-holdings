# INDEX.json lint compared JSON strings, so serialisation differences looked like drift

**ID:** BUG-84e037f13
**Date:** 2026-09-25
**Resolved:** closed
**Commit:** `84e037f`
**Issue:** (none - conventional-commit fix: without an issue reference)

## Symptom

After sorting fixed the ordering problem (BUG-93e21736a), `ECL Harness Lint` still failed on CI while passing locally. The "expected" and "actual" dumps printed by the lint were visually identical.

## Root Cause

`scripts/lint-ecl.ps1` canonicalised both sides with `ConvertTo-Json -Depth 8 -Compress` and compared the resulting strings with `-cne`. `ConvertTo-Json` output is not stable across PowerShell versions — empty-array rendering, escaping of non-ASCII, and number formatting differ between Windows PowerShell 5.1 and PowerShell 7.x. Two content-identical indexes therefore serialised to different strings, and the string comparison reported drift that did not exist.

## Fix

`scripts/lint-ecl.ps1` now parses both sides into objects, sorts by id, and compares property-by-property with:

```powershell
Compare-Object $actualObj $expectedObj -Property id,title,status,location,modules,files,tags,decisions,validation_status,path,updated_at
```

Only a real field difference can now fail the check.

## Files Changed

`scripts/lint-ecl.ps1`

## Diagnostic Commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/lint-ecl.ps1
```
On failure the lint prints `--- expected (index-json) ---` and `--- actual (INDEX.json) ---`; diff those to identify the offending field.

## Verification

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/lint-ecl.ps1   # ECL lint passed.
```
Reproduced the original failure in a clean `git worktree` (CI's exact state), applied the fix, and confirmed lint passes there.

## Pattern

JSON serialisation is an implementation detail of the runtime that produced it. Compare parsed structures, never the serialised text — especially across PowerShell editions.
