# INDEX.json regenerated in a different order on every platform

**ID:** BUG-93e21736a
**Date:** 2026-09-25
**Resolved:** closed
**Commit:** `93e2173`
**Issue:** (none - conventional-commit fix: without an issue reference)

## Symptom

`ECL Harness Lint` failed on CI with:

```
harness/changes/INDEX.json is stale. Run: powershell -NoProfile -ExecutionPolicy Bypass -File scripts/harness-change.ps1 reindex
```

Running the suggested `reindex` locally produced a diff of ~1100 lines against a file that had just been regenerated on the same machine — the content was identical but the entry order was not.

## Root Cause

`Get-IndexEntries` in `scripts/harness-change.ps1` returned entries in `Get-ChildItem` directory-enumeration order. That order is an implementation detail and is not stable across platforms (Windows PowerShell 5.1 vs Ubuntu PowerShell 7.x), so the regenerated INDEX.json on CI ordered entries differently from the committed one. `scripts/lint-ecl.ps1` then compared the two serialisations as strings and reported the file stale.

## Fix

- `scripts/harness-change.ps1`: `Get-IndexEntries` now returns `$entries | Sort-Object id`, making generation order deterministic on every platform.
- `scripts/lint-ecl.ps1`: the canonicaliser parses both sides, sorts by id, and re-serialises, so ordering can no longer cause a false failure.

## Files Changed

`scripts/harness-change.ps1`, `scripts/lint-ecl.ps1`, `harness/changes/INDEX.json`

## Diagnostic Commands

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/harness-change.ps1 reindex
git diff --stat harness/changes/INDEX.json
```
Re-running `reindex` twice must produce an identical file. A diff on the second run means ordering is still unstable.

## Verification

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/lint-ecl.ps1   # ECL lint passed.
```
Confirmed against a clean `git worktree` checkout (the same state CI sees): lint passes once entry order is stable.

## Pattern

Never let a generated file's byte layout depend on filesystem enumeration order. Sort explicitly at generation time *and* compare semantically, not as strings.
