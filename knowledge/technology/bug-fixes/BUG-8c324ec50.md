## Root Cause (filled by the resolving engineer)

Two independent defects survived on local main:

1. `src/components/FloatingNav.tsx` — conflict resolution `bb3059c0` put the
   governance overlay JSX outside the `return (` statement, leaving mojibake
   and spliced/duplicated lines. The follow-up commit `a1fe8548` closed the
   missing `}` but did not restore a structurally valid component, so
   `npx tsc --noEmit` still failed. Independently, conflict resolution also
   dropped the 7 page imports (`Architecture`, `Build`, `OfferA`-`OfferE`)
   from `src/App.tsx`.
2. `harness/changes/INDEX.json` + archive `summary.md` — commit `a3dd7af0`
   deduplicated session IDs but missed two pairs where **distinct** archive
   changes (different slugs/paths) were recorded under one session ID:
   `acf21912-6a5a-4666-bceb-3f7d773aed1d` (client-site phase-1 + phase-3)
   and `0ef66804-66ce-4568-ac4f-2841f9d012f7` (ls-mem implementation +
   phase-3 data model). The ECL lifecycle test asserts uniqueness across
   archive entries, so both pairs failed `test_no_duplicate_session_ids`.

## Fix (filled by the resolving engineer)

- Fully rewrote `FloatingNav.tsx` with correct structure:
  `return (<>...</header>{showGovernance && (...)}</>);` plus named and
  default exports (`SiteLayout.tsx` uses the named import).
- Re-added the 7 page imports to `src/App.tsx`.
- Re-identified the two phase-3 changes with fresh UUIDs at the source of
  truth (`summary.md`, read by `harness-change.ps1:180` on reindex):
  `eccdfd71-0cb6-4a34-bbbb-6605e2204911` (client-site phase-3) and
  `cdab4616-e15c-4221-9504-9767c32e0eaf` (ls-mem phase-3), then applied
  the matching 2-line edit to `harness/changes/INDEX.json` (kept HEAD's
  entry order; full reindex output was format churn and was discarded).
