## Root Cause (filled by the resolving engineer)

The required `Site Build + Principles Gate` check on PR #433 failed in
`bun run build` with:

```
[vite:load-fallback] Could not load .../data/use-cases/registry.ts
(imported by src/pages/UseCaseDetailPage.tsx): ENOENT
```

`vite.config.ts` aliases 12 `data/<dir>/registry.ts` files
(`@lightspeed/data/{company,metrics,capabilities,solutions,use-cases,sectors,insights,faqs,claims,governance,media,ctas}`),
but `.gitignore` had a blanket `/data/` rule (line 89), so none of those
registries were ever tracked. Local checkouts (author machine, Vite dev,
`npm run build`) resolve the files from disk and succeed; any clean
checkout (GitHub Actions, Vercel) lacks them and the site build cannot
resolve the aliases. The same aliases and imports already existed on
`origin/main` (`67f87b72`), which is why main's CI had been red — the PR
route could never go green without fixing this.

## Fix (filled by the resolving engineer)

Replaced the blanket `/data/` ignore with a precise pattern:

- `/data/*` ignores direct children of `data/` (runtime state: `agents/`,
  `orchestrator/`, `catalog/`, `*.db`, etc. stay ignored).
- For each of the 12 aliased directories, re-include the directory and its
  `registry.ts` only (`!/data/<dir>/` + `/data/<dir>/*` +
  `!/data/<dir>/registry.ts`), so future junk inside those directories
  does not get tracked by accident.

Then tracked the 12 `registry.ts` files. Pre-commit's
`trailing-whitespace` and `end-of-file-fixer` hooks applied whitespace/EOF
normalization to the newly tracked files; re-staged and committed.
