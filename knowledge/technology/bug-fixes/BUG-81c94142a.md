# INDEX.json committed while two parking dirs existed only as untracked files

**ID:** BUG-81c94142a
**Date:** 2026-09-26
**Resolved:** closed
**Commit:** `81c9414`
**Issue:** (none - conventional-commit fix: without an issue reference)

## Symptom

`ECL Harness Lint` failed on CI (PR #363) with `harness/changes/INDEX.json is stale`, but the identical check passed locally. Re-running `reindex` locally changed nothing.

## Root Cause

`harness/changes/INDEX.json` was regenerated and committed while these two directories existed **only as untracked working files**:

- `harness/changes/parking/2026-09-24-lightspeed-ai-company-builder-web-experience-architecture-v2-0`
- `harness/changes/parking/2026-09-24-lightspeed-ai-company-builder-web-experience-architecture-v2-0-2`

The committed index therefore referenced 38 paths, but CI checks out a clean tree with only 36. CI's `index-json` regenerated 36 entries, `Compare-Object` saw the 2 extras, and the lint reported drift. Locally the dirs were present, so the check passed — the failure was invisible on the machine that produced the commit.

Both directories are stale parked duplicates of a change that was subsequently archived (`status: completed`, `phase: validate`), which is why nobody noticed they had never been staged. Every other directory under `harness/changes/parking/` is tracked.

## Fix

`git add` the two directories so the committed index and a clean checkout agree. No index content changed — the entries were already correct.

## Files Changed

`harness/changes/parking/2026-09-24-lightspeed-ai-company-builder-web-experience-architecture-v2-0/**` (11 files), `harness/changes/parking/2026-09-24-lightspeed-ai-company-builder-web-experience-architecture-v2-0-2/**` (12 files)

## Verification

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\lint-ecl.ps1   # ECL lint passed.
```
Confirmed in a clean `git worktree` (CI's exact state): lint failed before the fix, passes after the two dirs were present.

## Pattern

A generated index is only as good as the inputs that were actually committed. Never regenerate and commit a manifest while its inputs are untracked — verify with a clean checkout, not the working tree.
